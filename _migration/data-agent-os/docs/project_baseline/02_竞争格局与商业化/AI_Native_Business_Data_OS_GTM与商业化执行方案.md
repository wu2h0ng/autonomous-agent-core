## 1. 理想客户画像（ICP）第一版

当前项目以 FaSoLa 作为 Customer-0 进行内部孵化验证。FaSoLa 提供真实业务场景和数据闭环，但不是真实市场验证。以下定义第一版 ICP，用于指导销售和产品方向：

### 1.1 核心ICP参数

| 维度 | 标准 | 排除 |
|---|---|---|
| 规模 | 200-2000人，年营收 5000万-50亿 | 微型创业公司（无数据团队），超大型传统集团（采购周期>12个月） |
| 数据团队 | 独立数据团队3人以上，有数据分析师或数据工程角色 | 无专职数据人员，完全依赖外包 |
| 行业 | 内容电商、新消费品牌、DTC、SaaS企业、零售连锁 | 传统制造（数字化基础弱）、强监管金融（合规代价高）、政务（采购流程特殊） |
| 数据基础设施 | 已有数仓/数据湖/BI工具，有结构化业务数据 | 尚无基本数据基础设施，数据散落Excel |
| 核心痛点 | "提数慢、口径乱、洞察不落地"是明确痛点，已有过内部提效尝试 | 仍在"要不要建数仓"阶段的组织 |
| 决策人 | 数据负责人(CDO/数据总监)或业务VP，有50万+/年预算权 | 仅IT运维角色采购（无法驱动业务采用） |
| 技术偏好 | 对AI工具持开放态度，愿意参与产品共建 | 对AI零信任，要求100%人工兜底 |

### 1.2 ICP分级

| 级别 | 画像 | 预期转化周期 | ACV预期 |
|---|---|---|---|
| S级 | 内容电商头部/DTC品牌，数据团队10人+，已有数仓+BI，提数周期>3天 | 2-4周 | 50万+/年 |
| A级 | 新消费/零售连锁，数据团队5-10人，有BI但口径争议频繁 | 4-8周 | 20-50万/年 |
| B级 | SaaS/中型企业，数据团队3-5人，正在评估ChatBI方案 | 8-12周 | 10-20万/年 |

## 2. GTM阶段规划

### 2.1 三阶段总览

```text
阶段1（0-6个月）：深度服务 → 1-2个参照客户
阶段2（6-18个月）：行业复制 → 细分市场Top 20
阶段3（18-36个月）：规模化 → 产品主导增长 + 生态
```

### 2.2 阶段1：深度服务（0-6个月）

**目标**：在1-2个行业头部客户中跑通完整闭环，产出可公开的案例和量化ROI数据。

| 要素 | 内容 |
|---|---|
| 客户数量 | 1-2个参照客户（不含FaSoLa） |
| 获取方式 | 创始人关系网络 + 行业圈子推荐，不投放广告 |
| 定价策略 | 参照客户优惠价或免费（换取案例权、背书权、产品共建） |
| 服务模式 | 创始团队直接驻场/深度协作，不做轻量自助 |
| 成功标准 | 至少1个客户每周活跃使用≥5次，至少1个ActionProposal被采纳，至少产出1个可复用的Domain Pack |
| 退出标准 | 如果6个月后无客户愿意付费续约，进入pivot评估 |

**关键动作**：
- 定义"参照客户协议"模板（含案例使用权、联合PR权利、数据隔离条款）
- 每周和参照客户做一次产品回顾+需求收集
- 按月产出"客户健康度报告"（使用频次、EvidenceChain生成量、NPS趋势）

### 2.3 阶段2：行业复制（6-18个月）

**目标**：基于参照客户成功案例，在1-2个细分行业扩展至5-10个付费客户。

| 要素 | 内容 |
|---|---|
| 销售模式 | 创始人/CEO主导的企业直销 + 行业会议/圈子口碑 |
| 目标行业 | 从首发验证行业（内容电商）开始，再扩展到新消费/DTC |
| 定价 | 从参照价过渡到标准定价（见第3节） |
| 服务模式 | 1个客户成功经理覆盖3-5个客户，不再驻场 |
| 产品重点 | Domain Pack可复制性、数据引导(onboarding)体验、自助配置能力 |
| 成功标准 | NRR > 100%，至少1个客户完成从POC到年付签约，至少1个SI合作伙伴接洽 |

### 2.4 阶段3：规模化（18-36个月）

**目标**：建立产品主导增长飞轮，合作伙伴生态开始产生线索。

| 要素 | 内容 |
|---|---|
| 销售模式 | 产品主导增长(PLG) + 合作伙伴渠道 |
| PLG抓手 | 免费试用workspace（1数据源、50次EvidenceChain/月）、开放Domain Pack SDK |
| 合作伙伴 | 2-3个SI活跃交付、至少1个ISV发布Domain Pack |
| 产品重点 | Marketplace、自助onboarding ≤ 1天、自助定价升级、社区运营 |
| 成功标准 | 合作伙伴线索占比 > 30%，自助注册转化率 > 5%，NRR > 110% |

## 3. 定价策略

### 3.1 定价原则

1. **价值锚定，而非成本加成**：定价基于客户节省的"数据需求交付时间"和"错误决策损失"，而非我们的服务器成本
2. **按使用量阶梯，而非按席位数**：鼓励组织内扩散使用，不用席位费制造摩擦
3. **参照客户例外**：前3个付费客户可享受"共创价"，换取案例权和产品反馈
4. **中国市场特殊考量**：人民币定价需考虑国内企业IT预算结构（通常低于美国同类50-70%）

### 3.2 三档定价

| 版本 | Starter | Professional | Enterprise |
|---|---|---|---|
| **年费(RMB)** | ¥19,800 | ¥98,000 | ¥500,000+ |
| **年费(USD等效)** | $2,400 | $12,000 | $60,000+ |
| **工作区** | 1个 | 5个 | 无限 |
| **数据源** | 3个 | 10个 | 无限 |
| **MetricContract** | 50个 | 无限 | 无限 |
| **EvidenceChain/月** | 1,000次 | 20,000次 | 无限 |
| **ActionProposal** | 基础版(提案+审批) | 完整版(含任务分配) | 自定义工作流 |
| **部署** | 云(SaaS) | 云+Hybrid可选 | 云/Hybrid/On-prem |
| **RBAC** | 基础角色 | 高级RBAC | 自定义角色+SCIM |
| **审计日志** | 30天 | 1年 | 自定义保留 |
| **SLA** | 99.5% | 99.9% | 99.95% + 专属 |
| **客户成功** | 社区+文档 | 专属CSM | 专属CSM+季度业务回顾 |
| **Model BYO** | 不支持 | 支持 | 支持+专属调优 |

### 3.3 定价心理学锚点

- Starter定价¥19,800/年 ≈ 一个初级数据分析师月薪的1.5倍 → 设定"替代半个人力"的价值锚
- Professional定价¥98,000/年 ≈ 一个高级数据分析师年薪的1/3 → 设定"放大团队效率"的价值锚
- 每档之间4-5倍价格差，制造合理的升级动力
- 所有定价公示在官网，不做暗箱报价（建立信任）

### 3.4 关键商业指标

| 指标 | 目标值(12个月) | 目标值(24个月) |
|---|---|---|
| ACV(年均合同价值) | ¥15-30万 | ¥30-80万 |
| CAC(客户获取成本) | < ACV的50% | < ACV的30% |
| CAC回收期 | < 12个月 | < 8个月 |
| NRR(净收入留存) | > 100% | > 110% |
| LTV/CAC | > 3x | > 5x |
| 毛利率(不含模型成本) | > 80% | > 85% |

## 4. 客户成功路径

### 4.1 成功里程碑（Success Milestones）

客户从签约到价值实现的路径需要明确节点定义，这直接影响售前承诺、实施方法论和续约理由。

| 里程碑 | 时间 | 定义 | 验证方式 |
|---|---|---|---|
| M0: 签约上线 | Day 0 | 完成数据源接入和核心指标配置（≥5个MetricContract） | 系统自动检测 |
| M7: 首次激活 | Day 7 | 第一条完整的EvidenceChain被生成并得到用户确认 | CSM确认+系统日志 |
| M30: 习惯建立 | Day 30 | 每周活跃问题数 ≥ 5，至少3个MetricContract稳定运行 | 产品数据看板 |
| M60: 价值感知 | Day 60 | 10个MetricContract稳定运行，Golden Query覆盖核心业务问题 | Golden Query覆盖率 ≥ 70% |
| M90: 行动闭环 | Day 90 | 第一条ActionProposal被采纳并有执行结果反馈 | 系统日志+用户访谈 |
| M180: 组织锁定 | Day 180 | 知识资产库 ≥ 50条，产品替代了原有报表需求的30%以上 | 使用数据+用户调研 |

### 4.2 客户健康度评分

| 维度 | 健康信号 | 风险信号 |
|---|---|---|
| 使用频率 | 周活跃问题数稳定或上升 | 连续2周下降 > 30% |
| 使用深度 | EvidenceChain → ActionProposal转化率 > 10% | 只提问不采纳 |
| 扩展性 | MetricContract数量持续增加 | 指标数停滞不前 |
| 满意度 | NPS ≥ 40 | NPS < 0 或关键用户流失 |
| 依赖性 | 知识资产沉淀量持续增长 | 知识资产为0 |

### 4.3 客户成功团队配置（随时间演进）

| 阶段 | 团队 | 服务比 |
|---|---|---|
| 阶段1(0-6月) | 创始团队直接服务 | 1:1-2 |
| 阶段2(6-18月) | 1名CSM + 创始团队backup | 1:3-5 |
| 阶段3(18-36月) | CSM团队 + 技术支持 + 社区 | 1:10-20 |

## 5. 合作伙伴生态

### 5.1 三类合作伙伴

| 类型 | 角色 | 收益模式 | 早期目标 |
|---|---|---|---|
| **SI(系统集成商)** | 企业大客户部署、实施、定制开发 | 实施费分成(20-30%) + 转售佣金 | 识别2-3家，优先有数据中台交付经验的 |
| **ISV(独立软件开发商)** | 开发垂直行业Domain Pack、Provider、Action Connector | Marketplace收入分成(70/30) | 接触3-5家，优先内容电商/零售ISV |
| **数据供应商** | 提供第三方数据源Provider(市场数据、舆情、竞品) | Provider调用量分成 | 识别2-3家，优先已有API产品的 |

### 5.2 SI合作伙伴画像

- 已服务过20+企业数据/BI项目
- 团队有数据工程+业务分析混合能力
- 对"AI替代传统BI"有战略焦虑，需要新武器
- 优先：用友/金蝶体系服务商、德勤/安永数据团队、区域性数据中台服务商

### 5.3 合作伙伴引入节奏

```text
阶段1(0-6个月)：不做合作伙伴。创始团队直接服务验证客户，积累实施经验
阶段2(6-18个月)：接触SI，选择1家做联合交付试点，产出合作方法论
阶段3(18-36个月)：正式启动合作伙伴计划，开放Domain Pack SDK和Marketplace
```

## 6. 数据飞轮与网络效应

### 6.1 项目的五层飞轮

当前方案未显式建模数据飞轮机制。以下是本项目的核心飞轮：

```text
层1 - 使用飞轮：
  更多用户提问 → 更多EvidenceChain → 更多知识资产沉淀 → 更好的答案质量 → 更多用户使用

层2 - 数据飞轮：
  更多MetricContract → 更准确的语义理解 → 更高的自动匹配率 → 更快的onboarding → 更多客户

层3 - 评测飞轮：
  更多Golden Query → 更准确的回归测试 → 更稳定的模型表现 → 更多信任 → 更多采纳

层4 - 生态飞轮：
  更多Domain Pack → 更低的新行业进入成本 → 更多客户 → 更多ISV加入 → 更多Domain Pack

层5 - 模型飞轮(远期)：
  企业知识资产积累 → 企业特定微调数据 → 垂直模型精度提升 → 差异化模型能力 → 更高迁移成本
```

### 6.2 飞轮启动策略

| 飞轮 | 启动策略 | 关键指标 |
|---|---|---|
| 使用飞轮 | 参照客户深度服务，确保前10个MetricContract高质量 | 周活跃问题数 |
| 数据飞轮 | 冷启动阶段自动推荐指标候选，降低配置门槛 | MetricContract自动匹配率 |
| 评测飞轮 | 每解决一个客户问题，同步纳入Golden Query | Golden Query覆盖率 |
| 生态飞轮 | 先从内容电商Domain Pack做起，验证可复制性 | Domain Pack复用率 |
| 模型飞轮 | 等知识资产≥1000条后再启动，早期不做 | 企业微调模型vs通用模型精度对比 |

### 6.3 核心防御壁垒（随时间累积）

| 时间 | 壁垒来源 |
|---|---|
| 0-12个月 | 产品体验 + 参照客户信任 + EvidenceChain设计深度 |
| 12-24个月 | 知识资产存量 + Golden Query覆盖率 + Domain Pack可复制性 |
| 24-36个月 | 生态网络效应 + 垂直模型精度 + 客户迁移成本 |

## 7. 国际化路径

### 7.1 国际化三阶段

| 阶段 | 时间 | 目标市场 | 策略 |
|---|---|---|---|
| 国内深耕 | 0-24个月 | 中国内容电商、新消费、DTC | 打磨产品、积累案例、建立定价基准 |
| 亚太扩展 | 24-36个月 | 东南亚(Shopee/Lazada生态)、日本(乐天生态) | 与当地电商SaaS厂商合作分销，轻量本地化 |
| 全球扩展 | 36个月+ | 北美DTC品牌、欧洲零售 | 英文版Domain Pack、接入Shopify/Amazon生态 |

### 7.2 国际化前置条件

- 产品完成从"中文+中国电商"到"多语言+通用商业"的Domain Pack抽象
- Model Gateway已稳定支持海外模型(OpenAI/Anthropic/Google)
- 至少有1个海外参照客户完成验证
- 团队有国际化产品经验的人加入

### 7.3 目标市场优先级矩阵

| 市场 | 市场规模 | 竞争强度 | 进入难度 | 优先级 |
|---|---|---|---|---|
| 中国内容电商 | 中 | 中(Aloudata等) | 低 | P0(首发) |
| 东南亚电商 | 中 | 低 | 中 | P1(第二站) |
| 日本电商 | 中 | 低 | 高(语言/商业习惯) | P2 |
| 北美DTC | 大 | 高(Snowflake/Palantir) | 高 | P2 |
| 欧洲零售 | 大 | 中 | 高(GDPR合规) | P3 |
