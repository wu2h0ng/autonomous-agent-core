# AI Native Business Data OS 定位差异与投资人沟通报告

> 日期：2026-06-01  
> 用途：投资人沟通、融资材料底稿、对外战略叙事。  
> 口径：本报告保留商业判断，但弱化内部工程细节和过多防守性表达。

---

## 1. 一句话定位

我们构建的是企业 AI Agent 时代的业务生产操作系统。

它把业务问题编译为可信数据产品、可验证的数据证据、可审批可追溯的业务行动、反馈学习和企业知识资产。

```text
Business Question
  -> Trusted Data Evidence
  -> EvidenceChain
  -> Governed Action Proposal
  -> Approval / Execution Trace
  -> Feedback / Enterprise Knowledge
```

这不是传统 BI，也不是通用聊天机器人，而是企业从“看数据”走向“用可信数据驱动行动”的下一代操作层。

---

## 2. 投资判断

企业 AI 的第一波是“能回答问题”。  
第二波是“能完成任务”。  
真正可规模化商业化的第三波，是“能在企业责任体系内可信地完成任务”。

企业不会把关键业务交给一个只会生成答案的 Agent。它们需要：

- 数据口径可信。
- 证据可追溯。
- 权限可控制。
- 行动可审批。
- 执行可审计。
- 结果可复盘。
- 经验可沉淀。

这正是我们的产品切口。

市场已经被 Agentic BI、Data Agent、数据云和 Palantir 类产品验证。其中，Aloudata 是当前中国市场最重要的核心竞争者之一：它通过 AIR 数据编织、BIG 主动元数据、CAN 指标平台和 Agent 分析智能体，已经证明 AI-ready data foundation 是企业刚需。但尚未出现一个从数据编织、指标语义、可信分析继续走到受治理业务行动、反馈和知识资产的标准产品。

我们的长期生态位不是 Aloudata 旁边的差异化应用，而是：

```text
AI-ready Data Foundation
  + Agent-ready Business Operation
  + Enterprise Knowledge Asset
```

也就是说，Aloudata makes enterprise data AI-ready；我们要 make enterprise business agent-ready。

---

## 3. 为什么现在是窗口期

### 3.1 企业已经不缺 dashboard

过去十年，企业大量投资数仓、BI、报表、指标平台和数据中台。但核心流程仍然断裂：

```text
业务提问题
  -> 数据团队取数
  -> BI 或报表输出
  -> 人工解释
  -> 人工到另一个系统执行
  -> 结果难以反馈和复盘
```

AI 让自然语言问数变容易，但它没有自动解决“可信、审批、执行、反馈”的责任链问题。

### 3.2 Agentic BI 正在快速教育市场

Aloudata、帆软 Dora、SmartBI 白泽、ThoughtSpot Spotter、Tableau Next、Snowflake Intelligence 等产品都在证明同一个趋势：

企业需要的不再只是 BI，而是能理解业务语义、主动分析、生成报告、推送预警、进入工作流的 Data Agent。

这为市场教育提供了强验证。

### 3.3 但 Agentic BI 的终点仍然不够

多数产品仍停留在：

```text
智能问数
归因分析
自动报告
异常预警
行动建议
```

我们要进入下一段：

```text
证据链
行动提案
审批
执行记录
反馈
知识资产
```

这使我们有机会避免和 BI 厂商在第一战场正面竞争。

## 4. 产品到底是什么

### 4.1 核心产品对象

| 对象 | 作用 |
|---|---|
| BusinessIntent | 业务问题和目标的结构化表达 |
| MetricContract | 指标口径、owner、计算规则和质量要求 |
| DataProduct | 可复用、可验证的数据产品 |
| EvidenceChain | 答案背后的数据、SQL、口径、质量、权限和限制 |
| ActionProposal | 基于证据生成的业务行动提案 |
| ApprovalRecord | 人类责任人和审批路径 |
| OperationTrace | 从问题到行动的端到端记录 |
| FeedbackAsset | 执行结果和复盘经验 |
| KnowledgeAsset | 可治理、可复用的企业知识资产 |

### 4.2 MVP 形态

第一版不做完整 OS，而是聚焦一个可销售、可验证的闭环：

```text
可信问数
  -> EvidenceChain
  -> 行动提案
  -> 轻审批
  -> 反馈记录
```

这让产品既有长期平台潜力，又不会在早期被平台工程拖慢。

## 5. 市场中的同行

市场上有相邻玩家，说明方向被验证；但它们各自被原有生态约束。

### 5.1 Palantir

Palantir AIP / Foundry 是长期最接近的参照。它通过 Ontology 把企业的数据、逻辑、行动和安全整合起来，支持 AI 在受控边界内参与决策和行动。公开文档中，Palantir 明确强调 action loop、writeback、human review、audit 和 decision lineage。

它证明了终局成立：企业级 AI 的价值来自 operational AI，而不是聊天框。

我们的机会是更轻量、更开放、更适合从部门级闭环切入。

### 5.2 帆软 Dora

帆软 Dora 从 BI 和数据治理升级到 Data Agent，结合 FineReport、FineBI、FineDataLink、知识库、LLM 和 Agentic Workflow，形成数据分析师、日报推送秘书、风险预警官、报告研究员等数字员工。

它证明国内企业正在接受“Data Agent / 数字员工”。

我们的差异是：不以 BI 资产激活为终点，而以 EvidenceChain 和受治理业务行动为终点。

### 5.3 SmartBI 白泽

SmartBI 白泽强调企业级 AgentBI、智能问数、归因分析、智能报告，并支持接入已有报表、仪表盘、数据集和指标模型。

它证明存量 BI 资产可以被 AI 重新激活。

我们的差异是：不仅生成分析和报告，还把结论组织成可审批、可追溯、可反馈的业务行动。

### 5.4 Aloudata AIR / BIG / CAN / Agent

Aloudata 是当前最核心的中国市场竞争者之一。它不是单一 Agent 产品，而是由 AIR 数据编织、BIG 主动元数据、CAN NoETL 指标平台和 Agent 分析智能体组成的产品族。

它已经覆盖企业 AI-ready data foundation 的关键底座：

- AIR 解决数据编织、逻辑集成、数据虚拟化和查询加速。
- BIG 解决主动元数据、算子级血缘和 DataOps 治理。
- CAN 解决指标定义、指标一致性和自动化指标生产。
- Agent 解决基于语义层的问数、归因、报告和趋势分析。

因此，我们的竞争姿态不是绕开 Aloudata 做差异化，而是：它能做的事，我们要做得更好；它尚未做深的业务行动、审批、反馈和知识资产，我们也要做。

投资人沟通中可以这样表达：

```text
Aloudata makes enterprise data AI-ready.
We make enterprise business agent-ready.
```

### 5.5 Snowflake、Tableau、ThoughtSpot、Databricks、Microsoft

这些国际厂商从数据云、语义层和 BI 生态出发，正在把 AI Agent 嵌入数据分析和企业工作流。

它们的优势是平台、客户和数据基础设施。  
它们的限制是通常绑定既有生态。

我们的机会是做跨数据栈、跨 BI、跨业务系统的轻量可信行动层。

### 5.6 腾讯 Marvis

Marvis 是个人电脑和本地文件场景的操作系统级 AI 助手，强调本地模型、本地文件 0 上传、手机操控电脑、文件智能整理和系统设置修改。

它不是直接竞品，但证明用户正在接受：

- 本地数据不出域。
- Agent 执行过程可见。
- 高风险动作需要确认。
- 本地文件和桌面数据是重要入口。

这对我们后续 Hybrid Connector / Local Agent 有启发。

## 6. 我们和同行的差异

| 维度 | 主流 Agentic BI | Palantir | 我们 |
|---|---|---|---|
| 入口 | 问数、报表、分析 | 企业 ontology 和 operational workflow | 业务问题 |
| 核心资产 | 语义层、报表、数据集 | Ontology、action、decision lineage | EvidenceChain、MetricContract、ActionProposal、FeedbackAsset |
| 输出 | 图表、报告、归因、建议 | 受控行动和业务应用 | 可审批行动提案和可追溯闭环 |
| 部署复杂度 | 中等，依赖 BI/数据平台 | 高，重交付 | 轻量，从部门级闭环开始 |
| 竞争路径 | 激活 BI 资产 | 建企业 operating model | 跨 BI/数仓/业务系统建立可信行动层 |
| 早期可落地性 | 高 | 中低 | 高，聚焦 MVP 闭环 |

我们的品类差异可以概括为：

```text
Agentic BI stops at insight.
We turn trusted insight into governed action.
```

中文表达：

```text
Agentic BI 停在洞察，我们把可信洞察变成受治理行动。
```

与 Aloudata 的差异需要单独表达。Aloudata 已经不是普通 Agentic BI，而是覆盖数据编织、元数据、指标和 Agent 的系统性竞争者：

| 维度 | Aloudata | 我们 |
|---|---|---|
| 数据编织 | AIR 逻辑数据平台、数据虚拟化、联邦查询、查询加速 | ProviderContract + DataProduct Compiler，从 BusinessIntent 自动生成数据获取和编译方案 |
| 元数据 | BIG 主动元数据和算子级血缘 | Semantic Object + DataProduct + EvidenceChain + OperationTrace |
| 指标 | CAN 指标定义、管理、一致性和自动化生产 | MetricContract 绑定 quality contract、evidence template、action candidate 和 feedback metric |
| Agent | 分析决策智能体，问数、归因、报告、趋势预测 | Data Agent 做同等分析，Business Agent 继续生成 ActionProposal、Approval、OperationTrace、FeedbackAsset |
| 终点 | AI-ready data 和分析决策 | Business-ready action 和组织反馈闭环 |

## 7. 为什么我们能切进去

### 7.1 从窄场景进入，而不是从大平台进入

不先卖 OS。先卖一个业务角色：

```text
可信经营分析师
异常诊断员
行动提案助手
复盘记录员
```

首发场景选择高频、低风险、可验证的问题，例如：

- 投放 ROI 下降。
- GMV 异常波动。
- 库存周转预警。
- 转化漏斗下降。
- 销售 pipeline 异常。
- 客服工单和客户流失风险。

### 7.2 从 EvidenceChain 建立信任

企业客户不缺 AI 答案，缺的是能被管理层、数据团队和业务负责人共同接受的证据。

EvidenceChain 能让客户看到：

- 指标口径。
- 数据来源。
- SQL 或查询计划。
- 数据质量结果。
- 权限范围。
- 结论限制。
- 行动依据。

这让产品从“AI 建议”变成“可审计业务依据”。

### 7.3 从行动提案切入，而不是高风险自动化

早期不承诺全自动执行业务动作。先做：

```text
建议
  -> 行动提案
  -> dry-run
  -> 审批单
  -> 任务
  -> 反馈
```

这既降低企业采用风险，也为后续自动化积累评测和信任。

| 产品包 | 内容 |
|---|---|

### 8.2 收费维度

- 工作区 / 部门订阅。
- 业务闭环数量。
- 数据产品数量。
- EvidenceChain 和审计留存。
- Agent run / workflow run。
- Domain Pack。
- Hybrid Connector。
- 私有化和运维服务。

早期不建议按 token 作为核心收费，因为客户更关心可预测业务价值。

## 9. 护城河

第一阶段护城河不是模型，而是业务闭环资产。

```text
Golden questions
Golden SQL
Metric contracts
EvidenceChain templates
Action proposal templates
Risk policies
Approval traces
Feedback outcomes
Domain eval packs
```

随着客户使用，系统会沉淀：

- 企业指标口径。
- 异常案例。
- 行动采纳记录。
- 审批理由。
- 执行结果。
- 复盘结论。
- 模型和 prompt 回归样本。

这些资产越多，系统越懂客户，也越难被通用 Agent 替代。

## 10. 里程碑

### 0 到 3 个月

目标：跑通可信问数和 EvidenceChain。

关键结果：

- 20 条 golden query。
- 30 到 50 个业务问题。
- 3 条黄金业务闭环。
- 所有正式答案都有 EvidenceChain。
- SQL Safety 100% 拦截危险语句。

### 3 到 6 个月

目标：从问数进入行动提案。

关键结果：

- ActionProposal。
- 风险分级。
- Approval lite。
- Trace lite。
- 业务 owner 每周评测。
- 行动提案采纳率可统计。

### 6 到 12 个月

目标：首个领域产品化。

关键结果：

- 首个 Domain Pack。
- 可复用 MetricContract 和 ActionProposal 模板。
- Eval Pack 稳定。
- 一个真实客户或准客户试点。
- 新增相似问题交付时间显著低于人工方式。

### 12 到 24 个月

目标：从单场景进入多场景平台。

关键结果：

- 第二业务域复用。
- Hybrid Connector。
- KnowledgeAsset registry。
- 更完整的 PolicyEngine。
- 与客户 BI、数仓、审批或任务系统集成。

## 11. 主要风险与应对

| 风险 | 应对 |
|---|---|
| BI 厂商快速补齐 Agent 能力 | 不在问数上硬拼，聚焦 EvidenceChain 和行动治理 |
| 数据云厂商从底层向上延伸 | 保持 BI-neutral 和 data-stack-neutral |
| Palantir 占据高端心智 | 以轻量、低成本、部门级闭环切入 |
| MVP 过重 | 严格只做可信问数、证据链、行动提案、轻审批 |
| 客户数据基础差 | 把 MetricContract、golden query、owner review 纳入交付 |
| AI 幻觉影响信任 | 任何正式输出必须有 EvidenceChain 和 eval gate |

## 12. 投资人版结论

企业 AI 的核心问题正在从“模型能不能回答”转向“企业敢不敢让它参与业务操作”。

敢用的前提是可信证据链和受治理行动闭环。

我们从最窄、最高频、最可验证的业务数据场景切入，先做可信问数和行动提案，再逐步扩展到数据产品、业务 Agent、审批执行、反馈资产和企业知识治理。

这是一条从 Agentic BI 进入 Business Data OS 的路径。

一句话：

```text
We build the enterprise Agentic Business OS that turns business intent into trusted data products, auditable evidence, governed operations, and reusable enterprise knowledge assets.
```
