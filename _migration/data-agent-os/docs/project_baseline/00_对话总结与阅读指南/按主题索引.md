## 1. 产品定位与北极星

核心问题：

```text
这个产品长期到底是什么？
它是不是 BI、Data Agent、Agent 平台或数据中台？
```

必读文档：

1. `01_战略定位与技术PRD/AI_Native_Business_Data_OS_生态位定义与Agent_OS长期定位.md`
2. `06_方案评估与落地边界/AI_Native_Business_Data_OS_理想产品形态.md`

4. `00_对话总结与阅读指南/对话总结.md`

关键结论：

- 产品不是传统 BI、数仓、ETL 或桌面助手。
- 长期生态位是 AI-ready Data Foundation + Agent-ready Business Operation + Enterprise Knowledge Asset。
- 核心是业务意图、可信数据产品、EvidenceChain、受治理业务行动和反馈。
- 内容电商只是首发验证场景，不是核心身份。

## 2. MVP 边界与阶段路线

核心问题：

```text
第一版到底做什么，不做什么？
```

必读文档：

1. `06_方案评估与落地边界/AI_Native_Business_Data_OS_阶段性落地方案.md`
2. `06_方案评估与落地边界/AI_Native_Business_Data_OS_MVP技术选型与工程工作流.md`

- 第一阶段只证明可复用 DataProduct candidate、EvidenceChain、受治理 ActionProposal、Feedback/Trace 与 KnowledgeAsset candidate 的最小业务生产闭环。

- 不做完整 OS、Marketplace、全私有化和高风险自动写操作。
- Temporal、OPA、OpenLineage、MCP Gateway 先留接口，不拖慢闭环验证。

## 3. 技术架构与工程选型

核心问题：

```text
后端、前端、Agent、数据、权限、异步任务和云算力如何选型？
```

必读文档：

1. `06_方案评估与落地边界/AI_Native_Business_Data_OS_MVP技术选型与工程工作流.md`
2. `01_战略定位与技术PRD/AI_Native_Business_Data_OS_技术PRD与架构设计.md`
3. `repo_scaffold/README.md`
4. `docs/decisions/`

关键结论：

- Python / FastAPI 作为控制面和编排层是合理选择。
- React / Next.js 作为 Web 工作台优先。
- PostgreSQL + JSONB + pgvector 支撑 MVP。
- Agent 框架第一版必须单选。
- Python 不负责大规模 OLAP 或高性能计算，重计算交给数据库、数据引擎或后续专用服务。

## 6. 市场、竞品与商业化

核心问题：

```text
市场上是否有同行？
我们和 Dora、SmartBI、Aloudata、Palantir 有什么差异？
```

必读文档：

1. `02_竞争格局与商业化/AI_Native_Business_Data_OS_商业与技术竞争格局报告_内部版.md`
2. `02_竞争格局与商业化/AI_Native_Business_Data_OS_Aloudata核心竞争者对标与全面超越策略.md`
3. `02_竞争格局与商业化/AI_Native_Business_Data_OS_GTM与商业化执行方案.md`
4. `02_竞争格局与商业化/AI_Native_Business_Data_OS_90天客户发现计划.md`
5. `02_竞争格局与商业化/AI_Native_Business_Data_OS_GTM九问与POC转付费销售手册.md`
6. `02_竞争格局与商业化/AI_Native_Business_Data_OS_商业假设与风险台账.md`
7. `02_竞争格局与商业化/AI_Native_Business_Data_OS_定位差异与投资人沟通报告.md`
8. `02_竞争格局与商业化/AI_Native_Business_Data_OS_竞争力深度分析.md`

关键结论：

- 市场已有相邻玩家，但没有完全同构赢家。
- Aloudata 是当前最核心的中国市场竞争者之一，不是普通相邻玩家。
- 对 Aloudata 的姿态是全面对标和上位替代：他们能做的事我们要做得更好，他们不能做的事我们也要做。
- 竞争策略不是绕开 Aloudata，而是把它代表的 NoETL、Data Fabric、主动元数据、指标语义层和分析 Agent 纳入自己的底座，再向业务生产 OS 延伸。
- 长期参照物是 Palantir。
- 完整生态位能力是 DataProduct Compiler + EvidenceChain + Governed Operation + KnowledgeAsset。
- 90 天内必须用真实客户验证 ICP、首发业务闭环、POC 转付费条件和旅伴客户意愿。
- 销售推进必须围绕九问：目标客户、最痛问题、现有系统、替代方案、现在性、预算、反对者、POC 转付费、闭环验收。
- 商业数字、ACV、CAC、POC 转化率和大厂追赶判断都必须作为假设管理，不能未经验证写成外部承诺。

## 7. 生态接入、安全与算力

核心问题：

```text
如何接入客户已有模型、工具、工作流、数据源和本地算力？
```

必读文档：

1. `03_生态接入_安全算力_组织范式/AI_Native_Business_Data_OS_生态接入_安全算力与组织范式.md`
2. `04_知识资产_组织权限_部署架构/AI_Native_Business_Data_OS_知识资产_组织权限与部署架构.md`
3. `06_方案评估与落地边界/AI_Native_Business_Data_OS_MVP技术选型与工程工作流.md`

关键结论：

- Model Gateway 是模型和 BYO Key 的唯一入口。
- MCP Gateway 是后续第三方工具治理入口，但 MVP 先留接口。
- Hybrid Connector 是企业内网接入的关键方向。
- MVP 不建议自购 GPU，优先 API 模型和 BYO Key。

## 11. ADR 与仓库脚手架

核心问题：

```text
重大技术决策如何留痕？
未来代码仓库怎么组织？
```

必读文档：

1. `docs/decisions/`
2. `repo_scaffold/README.md`
3. `code_index.md`

关键结论：

- 重大架构选择必须写 ADR。
- 未来代码目录必须围绕 `business_data_os` 核心和 `domain_packs`、`providers`、`action_connectors` 分层。
