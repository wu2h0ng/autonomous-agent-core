# 关键术语表

> 日期：2026-06-01  
> 用途：统一产品、技术、商业、工程和 Agent 开发中的核心概念，减少沟通偏差。

> 使用规则：本表提供快速查词；涉及项目一句话定义、愿景、价值主张、核心术语权威解释、工程落点和 Agent 误读防护时，以 `00_对话总结与阅读指南/项目定义与价值叙事基线.md` 为第一入口。

## 1. 产品定位类

| 术语 | 定义 |
|---|---|
| AI Native Business Data OS | 面向企业 AI Agent 时代的业务生产操作系统，把业务意图编译为可信数据产品、可验证证据、受治理业务行动、反馈学习和企业知识资产 |
| Business Data & Agentic Operations OS | 面向商业通用数据场景的长期产品身份，强调可信数据生产、业务行动智能、组织权限、反馈学习和知识资产闭环 |
| 可信业务数据行动平台 | 面向客户早期沟通的更轻表达，弱化 OS，强调可信数据、受治理行动、反馈和知识资产 |
| Agentic BI | 将 BI 问数、分析、报告、预警 Agent 化的产品方向 |
| Data Agent | 负责理解业务问题、解析语义、生成数据产品和 EvidenceChain 的 Agent |
| Business Agent | 消费 EvidenceChain，生成行动提案、审批、执行跟踪和反馈的 Agent |
| Governed Action Loop | 从证据到行动提案、审批、执行记录、反馈和知识沉淀的受治理闭环 |
| Business Data Control Plane | Business Data & Agentic Operations OS 内部负责策略、权限、路由、审计和治理的控制面能力；它不是产品全部身份 |
| AI-ready Data Foundation | 让企业数据可被 AI 理解、查询、治理和解释的底座能力，包括 NoETL、Data Fabric、语义层、指标和元数据 |
| Agent-ready Business Operation | 让企业业务动作可被 Agent 受控调用、审批、追踪、复盘和学习的业务生产能力 |
| 生态位吞并 | 本项目对 Aloudata 等核心竞争者的长期策略：覆盖其数据底座能力，并继续向业务行动、反馈、知识资产、生态接入与治理能力延伸 |

## 2. 核心对象类

| 术语 | 定义 |
|---|---|
| BusinessIntent | 业务问题或目标的结构化表达，替代传统报表需求 |
| MetricContract | 指标契约，定义指标名称、别名、公式、粒度、单位、owner、质量要求和 verified query |
| DataRequirement | 由业务意图推导出的数据需求，包括实体、指标、维度、时间窗口和数据新鲜度 |
| SQLTemplate | 可参数化、可审查、可复用的 SQL 模板 |
| QueryPlan | 查询计划，说明使用哪个模板、哪些参数、访问哪些表和字段 |
| QueryRun | 一次查询执行记录，包括 SQL、参数、用户、权限、结果摘要和 trace |
| DataProduct | 可复用、可验证、有版本、质量、血缘和证据链的数据产品 |
| EvidenceChain | 答案背后的证据链，包含问题、意图、指标、SQL、数据源、质量、权限、结论、限制和行动引用 |
| ActionProposal | 基于 EvidenceChain 生成的业务行动提案，包含原因、风险等级、审批建议和反馈指标 |
| ApprovalRecord | 审批记录，记录审批人、审批结果、理由、时间和责任归属 |
| OperationTrace | 从业务问题到行动执行和反馈的端到端操作记录 |
| FeedbackEvent | 业务动作执行后的结果事件，例如指标变化、任务状态、人工复盘 |
| KnowledgeAsset | 经过结构化、审核、版本化、权限控制和评测绑定的企业知识资产 |

## 3. MVP 分层类

| 术语 | 定义 |
|---|---|
| P0 | 必须进入 MVP 的能力，直接支撑可信问数、EvidenceChain 和行动提案闭环 |
| P1 | 轻实现能力，需要有抽象和最小实现，但不平台化 |
| P2 | 只留接口或方向，不能拖慢 MVP 闭环验证 |
| Trusted Loop | 第一阶段可信闭环，即业务问题到 EvidenceChain 到 ActionProposal 到 Approval lite 到 Feedback |
| Approval lite | MVP 的轻量审批记录，不等于完整 BPM 或企业审批平台 |
| Trace lite | MVP 的轻量追踪能力，先串起核心闭环，不等于完整 OpenTelemetry 或 OpenLineage |

## 4. 安全与治理类

| 术语 | 定义 |
|---|---|
| PolicyEngine | 统一判断权限、风险、审批、脱敏、模型调用和工具调用的策略抽象 |
| RiskLevel | 业务动作风险等级，R0 到 R5，从术语解释到预算、价格、库存、删除和权限变更 |
| SQL Safety | SQL 安全校验，包括 SELECT-only、schema 白名单、参数绑定、limit、危险语句拦截 |
| Purpose-based Access | 按使用目的控制访问，例如分析、审计、执行、训练、导出 |
| RBAC | 基于角色的权限控制 |
| ABAC | 基于属性的权限控制，例如部门、地区、数据分类 |
| ReBAC | 基于关系的权限控制，例如客户归属、项目成员、审批链 |
| PBAC | 基于策略的权限控制，例如高风险动作必须双人复核 |
| DLP | 数据泄露防护，识别和控制敏感字段、PII、财务和合同数据 |
| Audit Sink | 审计日志导出到客户 SIEM、对象存储或审计系统的能力 |

## 5. 生态与部署类

| 术语 | 定义 |
|---|---|
| Provider | 提供数据读取能力的连接器，例如数据库、文件、API、浏览器采集和事件流 |
| Action Connector | 提供业务写操作或业务任务能力的连接器，例如 CRM、ERP、广告、客服、工单、审批 |
| Model Gateway | 模型调用统一入口，管理 BYO Key、模型路由、预算、数据边界和调用 trace |
| MCP Gateway | MCP Server 和工具能力的治理入口，负责注册、鉴权、scope、沙箱、审计和风险分级 |
| Workflow Bridge | 与 Temporal、Airflow、Dagster、n8n、Power Automate 或客户自研工作流互操作的桥 |
| BYO Key | 客户使用自己的 AI API Key |
| BYO Model | 客户使用自己的模型服务 |
| BYO Compute | 客户使用自己的 GPU、云资源或本地算力 |
| Hybrid Connector | 部署在客户内网、主动出站连接 SaaS 控制面的连接器 |
| Local Connector | 运行在本地机器或内网环境的轻量连接器，可访问本地文件、浏览器、数据库或工具 |
| Desktop Agent | 后续可能用 Electron 或 Tauri 封装的本地桌面 Agent，不是 MVP 主产品 |

## 6. 评测类

| 术语 | 定义 |
|---|---|
| Eval Harness | 评测运行框架，用于跑 intent、metric、SQL、EvidenceChain 和 ActionProposal 回归 |
| Golden Question | 已知预期解析结果的业务问题样本 |
| Golden Query | 经过验证、可参数化、性能和结果已知的 SQL 查询 |
| Golden Business Loop | 从业务问题到证据链、行动提案和反馈的完整闭环样本 |
| Regression Case | 从失败样本沉淀而来的回归测试案例 |
| Evidence Completeness | EvidenceChain 是否包含必填证据字段的评测项 |
| Result Diff | 查询结果与 golden 结果之间的差异比较 |

## 7. 工程和 Code Agent 类

| 术语 | 定义 |
|---|---|
| Code Agent | 参与代码实现、测试、文档、审查或自动化任务的编码 Agent |
| Architecture Agent | 负责先做架构设计、边界判断、ADR 草案和 CTO 审批材料的 Agent |
| Implementation Agent | 在架构批准后执行具体代码实现的 Agent |
| Eval Agent | 负责新增、维护和运行评测用例的 Agent |
| Product Manager Agent | 辅助判断需求、开工资料、用户故事和验收标准是否完备的 Agent |
| Project Manager Agent | 辅助拆分任务、跟踪进度、维护依赖和风险的 Agent |
| ADR | Architecture Decision Record，架构决策记录 |
| Repo Scaffold | 未来代码仓库的目录蓝图和模块归属 |
| Code Index | 人类和 Agent 共用的项目索引，记录文档、模块、source of truth 和更新规则 |

## 8. 竞争和商业类

| 术语 | 定义 |
|---|---|
| Dora | 帆软 Data Agent / 数字员工方向产品，相邻竞品，强在 BI 资产和数据分析工作流 |
| SmartBI 白泽 | SmartBI 的 AgentBI 产品方向，相邻竞品，强在企业 BI、指标模型和智能分析 |
| Aloudata | 本项目在中国市场的核心竞争者之一，产品族包括 AIR 数据编织、BIG 主动元数据、CAN 指标平台和 Agent 分析智能体 |
| Aloudata AIR | Aloudata 逻辑数据编织平台，对标本项目 ProviderContract 和 DataProduct Compiler |
| Aloudata BIG | Aloudata 主动元数据平台，对标本项目 Semantic Object、DataProduct、EvidenceChain 和 OperationTrace 元数据体系 |
| Aloudata CAN | Aloudata NoETL 指标平台，对标本项目 MetricContract |
| Aloudata Agent | 基于语义层的分析决策智能体，对标本项目 Data Agent；本项目必须做到同等分析能力并继续进入 Business Agent 行动闭环 |
| Palantir AIP / Foundry | 长期最接近 Business Data OS 终局的参照，强在 Ontology、行动、安全和决策链 |
| Marvis | 腾讯桌面和本地文件 Agent，对本地模式、数据不上传和用户入口有启发 |
| EvidenceChain-first | 我们区别于普通 Agentic BI 的核心策略，先建立可信证据链，再进入行动 |
| Governed Action | 受风险分级、审批、审计、回滚或补偿约束的业务行动 |
| 上位替代 | 对 Aloudata 等核心竞争者的竞争姿态：兼容其能力，但产品上覆盖其数据编织、元数据、指标和 Agent，并继续延伸到行动、反馈和知识资产 |
| Lightweight Palantir | 内部理解用语，表示以轻量方式进入可信业务数据行动闭环；不建议作为对外口号 |

## 9. 推荐对外表达

避免：

```text
替代 BI
替代数仓
全自动运营
通用 Agent 平台
企业操作系统
```

优先：

```text
企业 AI Agent 时代的业务生产操作系统
把业务问题编译为可信数据产品和可验证证据
把可信洞察转化为可审批、可追溯、可复盘的业务行动，并沉淀为企业知识资产
```
