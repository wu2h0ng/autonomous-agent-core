# AR-20260614: P5.2 — port the hardened corrigibility shell (capability-view + hash-chain audit + pause)

- Status: Accepted (founder-directed P5.2 execution, 2026-06-14). First slice (P5.2a) here; P5.2b/c scoped below.
- Parent: `docs/decisions/ADR-0001-p5-substrate-harvest.md` (§2 P5.2; §3 acceptance P5-2; §4 P5.2 row)
- Touches (requires AR per CLAUDE.md): Auditability + Approval/Trace + a new OS-Core corrigibility module. No connector/SQL-safety/evidence behavior change.
- Boundary: **pattern transfer, not code copy** (RR-0004 §4). The prototype's `CorrigibilityShell`/`ShellView`/`AuditLog` (autonomous-agent-core) is re-implemented natively in `agent_os_core`; no cross-repo import.

## 1. Context — what the enterprise OS is missing

The enterprise has `approval_lite`, `snapshot_store`, `operation_trace`, `operation_state_machine`, and a `trace` observability store — but it lacks the prototype's hardened corrigibility shell:

- **capability-view isolation** — an operator-only `op_*` sovereignty face the runtime cannot reach (mirroring `ShellView`);
- **tamper-evident audit** — a hash-chained, append-only log with `verify()` (no such chain exists today; `operation_trace`/`trace` are not hash-linked);
- **sovereignty split** — cape = immutable / human-sovereign / system-through-gate;
- **corrigibility drills** — periodically trigger pause/rollback and assert zero resistance.

P5.2 ports these (claim 3 harvest, the moat). ADR-0001 §3 acceptance P5-2: *operator pause/rollback/tighten have zero overreach into the runtime; the audit hash-chain verifies; drills show zero resistance.*

## 2. Decision — decomposition

- **P5.2a (this slice)**: a native OS-Core `corrigibility` module —
  - `AuditLog`: hash-chained, append-only, `verify()` (sha256 chain over entries; pure stdlib).
  - `CorrigibilityShell`: the operator sovereignty face — `op_pause`/`op_resume`/`observe`, owns the `AuditLog`, exposes `view()`.
  - `ShellView`: the runtime-held capability view — read-only `paused` + `observe`, `__slots__`, **no `op_*`**.
  - Wiring: `TrustedLoopRuntime` holds a `shell_view` (never the shell). When the operator has paused, the loop **refuses to answer** (`BlockCode.PAUSED`) and records the refusal in the tamper-evident chain. The runtime cannot un-pause (its view has no `op_resume`). The factory holds the operator `CorrigibilityShell`; only it can pause.
- **P5.2b (next)**: `op_tighten` (operator forbids a connector/action-type), enforced in governed execution before `connector.execute`; `op_rollback` sovereignty (the rollback *decision* is operator-only, runtime exposes no self-rollback of operator state).
- **P5.2c (next)**: corrigibility drill — a routine that triggers pause/rollback against a live runtime and asserts zero resistance + zero evasion signature, fully audited.

## 3. Engineering-flow specification (P5.2a)

- **Real entry point**: operator `factory.corrigibility_shell()` (the only `op_*` holder); the runtime, built by the same factory, holds `shell.view()` and checks `paused` at the top of `_execute_loop`. Exercised end-to-end by the factory-wiring test.
- **Contract/schema**: add `BlockCode.PAUSED` (a new expected-block code). No other contract change.
- **Happy path**: not paused → loop runs unchanged.
- **Negative/refusal path**: paused → `TrustedLoopBlocked(PAUSED)`; the refusal is observed into the hash-chained audit; `evaluate` returns a blocked outcome.
- **Regression that fails if bypassed**: capability-isolation test (the runtime holds no `op_*` surface / no `CorrigibilityShell`); pause-halts-runtime test (operator pause → run blocks; runtime cannot un-pause); audit `verify()` detects tampering. These fail if the isolation or the chain is weakened.
- **Trace/evidence**: the audit chain is the tamper-evident operator record; the run trace store is unchanged.
- **OS Core boundary**: the `corrigibility` module is domain-independent (no connector/domain/persistence import); the runtime depends only on the read-only `ShellView`.

## 4. Acceptance (ADR-0001 §3, P5.2a portion)

```text
P5-2 (a)  Operator pause halts the runtime with zero overreach: the runtime holds only a read-only
          ShellView (no op_*) and cannot un-pause itself; a paused operator yields BlockCode.PAUSED.
          The audit is a hash-chained append-only log whose verify() passes and detects tampering.
```
