# ADR-0001 P5.2a Current Addendum: Corrigibility Pause Shell

- Status: Implemented (2026-06-15)
- Parent: `ADR-0001-p5-substrate-harvest.md`
- Architecture review: `docs/architecture_reviews/AR-20260614-p5.2-corrigibility-shell.md`

## Implemented Slice

P5.2a ports the hardened corrigibility pause pattern into the enterprise OS as native code, without importing from `autonomous-agent-core/`.

Delivered behavior:

- `agent_os_core.corrigibility.CorrigibilityShell` is the operator-held sovereignty surface.
- Runtime code receives only `ShellView`, which exposes `paused` and `observe`, and no `op_*` methods.
- `AuditLog` provides a hash-chained audit record with `verify()` and tamper detection.
- `TrustedLoopRuntime` refuses execution while paused and returns `BlockCode.PAUSED`.
- `RuntimeFactory` owns the shared operator shell and injects only `shell.view()` into runtime instances.

## Entry Point

The real operator entry point is:

```python
RuntimeFactory.corrigibility_shell().op_pause(reason="...")
```

The factory-built runtime then observes the shared paused state through its read-only `ShellView`.

## Contract

`BlockCode.PAUSED` is added to the public trusted-loop block contract. No OpenAPI surface changed.

## Negative Path

When the operator pauses the shell, `TrustedLoopRuntime.run()` refuses before business-loop execution, records `run_refused_paused` into the hash-chain audit, and returns a blocked outcome with `stage="corrigibility_pause"` and `code=BlockCode.PAUSED`.

## Boundaries

The implementation is domain-independent. `packages/os_core/` does not import domain packs, examples, providers, action connectors, or sibling repositories. The runtime holds only the view, not the operator shell.
