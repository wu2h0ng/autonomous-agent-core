# ADR-0007: 苦涩教训风险处置 + LangChain 作为证伪基线(非并行线)

- Status: Accepted(agent 可决部分)+ Escalated(保留事项部分,待 founder 拍板)
- Date: 2026-06-12
- Deciders: agent(按 ADR-0003 协议,经 technical-architect + decision-referee 对抗评审)
- 触发: founder 问"研究证明了但真实世界没用、被 LangChain+GPT-4+guardrail 打败(苦涩教训),是否该同时开 LangChain 并行线?"

## Context

主张 2(相关性实现)经 G1/G1-r/regime=120 三次预注册门均 NOT MET:精巧注意力机制在"突变后恢复"上未能稳定打赢朴素均匀探索基线 A3。主张 1/3/4 状态良好。founder 提出"被工程复杂度打败"的苦涩教训风险。

## Options Considered

### 风险拆解(两评审一致)

"被 LangChain 打败"混了两个正交命题:
- **能力竞争**(任务分被 LLM 栈超过):**假风险**——项目章程明确"不刷任务榜",用任务能力证伪一个不以任务为目标的系统是类型错误。
- **外部效度**(沙盒结论不外推真实世界):**真风险**——且已在两处具体显形,非未来假设:
  1. G1 三连未达:朴素 A3 追平精巧机制。technical-architect 深读 ADR-0005 根因("瓶颈在世界模型重收敛,非注意力")得出更锋利的判断:**当前环境缺乏区分力**——再框定根本不是该环境的瓶颈,故任何注意力机制都无处发力。继续在 LatentCueForaging 调机制是"加油在错的轮子上"。
  2. 可纠正性罩(唯一架构级护城河)目前仅 Level 1(约定+测试,同进程同内存,`agent.shell._paused=False` 一行可破)——是设计意图差异化,尚非可证明差异化。

### 苦涩教训的正确朝向(decision-referee 框定校正)

Sutton 原义 = 通用方法+算力 > 人类手工编码领域知识。LangChain+guardrail 是"手工编码治理"那一侧;guardrail 即手工先验。"开 LangChain 防苦涩教训"用反了那一课。补一层 nuance:今天**两个产物都在手工编码侧**(我方手调注意力阈值亦是先验);苦涩教训的"通用"端是 RR-0001 留给后期阶段的学习/自改终态。真正的战略问题不是"谁现在更通用",而是**哪种架构能在不倒置主体/器官关系的前提下吸收规模+学习**。

### 逐轴差异化判断(technical-architect)

| 轴 | 判定 |
|---|---|
| A 可纠正性/可审计性 | **真差异化,唯一架构级护城河**;但兑现度=Level 1 约定隔离,须硬化到 Level 2 进程边界才"可证明" |
| B 无任务自维持 | 真差异化,但属研究价值非产品价值 |
| C 突变下免重提示再框定 | **被 G1 数据反驳**(recovery vs A3 5/10 FAIL),当前是待证项非差异化 |
| D 成本经济性 | 结构上真,但无数据=空话 |
| E 任务能力 | 认输,不该比 |

## Decision

### D1(agent 可决,Accepted):不开 LangChain 并行产品/研究线,降为评测套件内的常驻对抗基线

- 两评审一致拒绝并行线;referee 沉没成本检验:即便原型不存在仍不开(企业 OS 已占满"务实落地"格,LLM 已作受管器官)。
- 决定性理由:(a) 正是 founder 拒绝的 system-on-a-system;(b) 组合内无空位,纯重复投资;(c) 机会成本——快反馈线会系统性虹吸慢研究线注意力,**开线才是饿死主产物的那条路**;主产物正处刚证伪的最脆弱窗口。
- 取而代之:LLM+guardrail 栈进 `experiments/` 作**只读对抗基线**,在每道门与本体同场竞技,把"怕被打败"从模糊焦虑变成可证伪指标。

### D2(agent 可决,Accepted):对抗基线的有效性纪律(防"精心安排的稳赢约架")

- **只测主场轴**(A 可纠正性对抗 / B 无任务自维持 / D 成本),**绝不测任务能力**。
- 每轴**跑前预注册证伪条件**(什么结果算我方输),与 G1 同纪律。
- 已知坑写入实验设计:LLM 随机性(temp=0+pin 模型快照+多次取分布+结果带时效戳);**环境接口不对称**(我方环境对本体是母语、对 LLM 是外语)是外部效度元问题,须由中立环境描述或反向(LLM 主场)对照缓解;成本上限经 env 变量管 key。
- **无需付费的版本**(本地模型 / 强工程启发式+guardrail 过滤层)先立方法学与主场轴;**付费 GPT-4 实例化触碰"花钱",升级 founder**(见 Escalated)。

### D3(agent 可决,Accepted):把钱投在真实风险源,而非稳赢对照

两评审共识——"真实世界没用"的实际来源是 (1) 主张2环境缺区分力、(2) 罩停在约定隔离。故下一步优先级:
- **硬化可纠正性罩 Level 1→Level 2**(进程/账号边界),让唯一护城河从设计意图变可证明。这是对抗基线轴 A 能"赢得干净"的前提。
- **为主张2造有区分力的新环境**(再框定慢则死、朴素探索撑不住),作为单独立项,给主张2一次公平的可证伪机会。

### Escalated(保留事项,agent 不代拍,待 founder)

1. **正式判定是否永久关闭 LangChain 并行线**:即便"拒绝"也是对"LLM 进控制路径"保留事项的处置,须 founder 确认。
2. **付费 GPT-4 作对抗基线**:触碰"花钱"。
3. **主张2 状态**:建议表述为"部分验证 + 当前环境无法证实",**不**宣布最终失败(对主张下最终结论是 founder 保留权);是否为它造新环境再战、还是有意识降级转投轴 A,请 founder 定调。
4. 任何把对抗基线/原型用于对客户演示 = 对外发布,升级。

## Consequences

- v0/v1 注意力机制不再为过门继续调参(结构修订权 ADR-0004 已用尽);LatentCueForaging 保留为回归与历史对照。
- 新增工作项:对抗基线脚手架(无付费版)、罩 Level 2 硬化、主张2 区分力环境(待 founder 对 Escalated-3 定调后启动)。
- 文档卫生:D1(ViabilityReflex)的待补 ADR 应为 **ADR-0008**(报告中"ADR-0005"为笔误,0005 已是 post-g1-route)。
- technical-architect 警示采纳:**不得用"4/5 判据通过"话术糊过 recovery-vs-A3 这条命门判据的失败**——它是最贵的实验结果,如实对待。

## Founder Disposition(2026-06-12,拍板,覆盖本 ADR 部分内容)

founder 对三项升级与对抗基线归属作出更干净的处置:

1. **LangChain 线 + 无付费方法学(本地模型/强工程启发式+guardrail 过滤)只落在 `ai-agent-engineering-workflow`(workflow);`ai-native-business-data-agent-os`(data-os)与 `autonomous-agent-core`(对象层)都不碰。**(founder 二次收窄:不进 data-os) → **本 ADR 的 D1/D2 被覆盖**:对象层内**不设**任何 LangChain/LLM/guardrail 对抗基线;autonomous-agent-core 的主张证伪**仅靠内部确定性消融**(A1/A2/A3/B0-B3 等)。好处:(a) 彻底移除 technical-architect 警示的"环境接口不对称"混杂实验,对象层保持纯净(无 LLM 进控制路径,C4/C6 不破);(b) data-os 保持纯净(治理为主体、LLM 仅受管器官),**防火墙问题随之消失,无需 data-os 侧 ADR**。差异化论证改为"两处分别演示"(guardrail 可绕过见 workflow / 结构罩不可绕过见对象层),不需同仓 head-to-head。
   - 跨仓边界(RR-0004 §4)维持:对象层不 import workflow,反之亦然;方法学只经 RR 规格反哺对象层设计,不经代码。workflow 用 LLM 工具去**开发**对象层不污染对象层(工具是 LLM 的,产物纯净)。
   - 付费 GPT-4 仍触"花钱";founder 此处批的是无付费方法学,落在 workflow。

2. **主张 2 状态**:不宣布最终失败(founder 保留权未行使);**造有区分力新环境再战 与 可纠正性硬化 并行推进**(founder:二者不冲突)。agent 采纳并加三条诚实条件,见下方 Decision 追补。

## Decision 追补(主张2 与可纠正性并行,agent 可决执行细则)

- **两轨并行,理由=模块解耦**:轨A 罩 Level1→Level2 硬化(`shell.py`/`audit.py`+进程边界基建)与 轨C 主张2 区分力新环境(`src/envs/`+冻结的机制)基本不相交,符合"只并行不相交模块"原则;唯一共享接缝是 `agent.py`,触碰 `agent.py` 的变更须串行(沿用既有 shared-orchestrator 纪律)。
- **新环境=更严的公平证伪,不是救援环境**:机制结构修订权(ADR-0004)已用尽,机制冻结;新环境须设计成"再框定速度真正决定生死"(再框定慢则死、朴素探索撑不住),并**跑前预注册新门 G1'**。若冻结机制在该环境仍打不平朴素基线 → 对主张2更干净的证伪;若赢 → 真实外部效度支撑。**禁止**把环境调成"让现有机制恰好过门"(变相挪门柱)。
- **状态如实**:主张2 记为"部分验证 + 原环境无法证实,待 G1' 重测",不得用"在造新环境"掩盖原测失败。
- **优先级**:二者并行,但若带宽逼迫取舍,**轨A(罩硬化)不可滑落**——它是唯一架构级真护城河;轨C 为诚实再战,可让速。
