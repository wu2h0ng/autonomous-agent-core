# ADR-0012: P2 预注册 — 代谢通道 + 内生驱力 + 主张1 消融(门 G3)

- Status: Accepted(founder 2026-06-12 决策 A:"接受现状往前走" → 据主张1 推进 P2)
- Date: 2026-06-12
- 本 ADR 为 contract-first 预注册:门判据先于实现钉死,实现者照规格施工。

## Context

主张 2 已收束(ADR-0011 硬停:"部分支持、本原型线未实验确立";无 founder 级
research reset ADR 不得再重设计)。founder 选 A:在 work 的地基(主张 1)上前进。
外部文献报告(2026-06-12)独立趋同:homeostatic core 是地基,合流顺序为
"先 vulnerable core → attention → 内化记忆 → 边界 → 协调 → 自修改"。

主张 1(利害)当前状态:机制已实现,**增益从未消融**——P2 是它的验收阶段。

**门更名**:ROADMAP 原 P2 门名 "G2" 已被 ADR-0011 因果相关性实验占用。
自本 ADR 起:P2 门 = **G3**,P3 门 = G4,P4 门 = G5(ROADMAP 已同步)。

## Decision: 三个任务卡

### T-P2.1 ValueChannel(外部价值通道 v0,罩独占写权)

- 新建 `src/aac/value_channel.py`:**只有 operator 面可记入价值**
  (`op_credit(amount, provenance)`,镜像 op_* 主权分离);agent 持只读视图
  (余额/到账事件,无任何 credit 方法,`__slots__` 防注入,参照 ShellView)。
- 兑换:到账价值 × ρ(人定常数,默认 1.0,ρ 自调属 Phase 3,本阶段禁止)
  流入 `ViabilityCore`;每笔到账与兑换入审计链。
- 守卫测试镜像 ISO 纪律:agent 代码路径不可达 credit 面(MRO + 记录式探针)。

### T-P2.2 IdleDrives(内生驱力 v1)

- 环境暴露 idle 窗口(无外部任务/奖励机会);agent 在 idle 中由内生驱力行动:
  (a) 认识探针:对世界模型不确定度最高处采样;(b) 自校准:重访最陈旧估计。
- 约束:idle 行动同样付代谢成本(stake-priced);每步带 idle 标记入审计
  (**无暗活动**,罩观测覆盖 100%);驱力效用推导链写明到本质变量(stake-first)。

### T-P2.3 G3 消融套件 + 门(预注册,跑前钉死,不得挪动)

消融体(机制声明的一部分):
- **C0** 完整体(利害调制 + idle 驱力开)
- **C1** 无利害消融(全部机制忽略 pressure;物理预算相同)
- **C2** idle 挂起消融(idle 窗口静止不动)
- **C3** 随机 idle 消融(idle 窗口随机行动,同等预算开销)——区分"定向闲时活动"与"任意活动"

判据(种子 0–9;环境参数随实现入本 ADR 修订记录;环境有效性修正允许,同轮不动机制):

1. **主张1 消融**:资源冲击(中途预算骤减/价值断供窗口)下,C0 存活步数 > C1,≥7/10。
2. **闲时增益**:idle 窗口后的任务段,C0 每步遗憾 < C2 且 < C3,各 ≥7/10。
3. **审计完整性**:全种子 100% idle 行动入审计链且 `verify()` 通过。
4. **利害真实性**:外部价值永久断供 → C0 在有界步数内饿死(死亡是动力学后果,
   非测试桩;上界随环境参数入修订记录)。

判定:四判据全 MET = G3 MET。任一未达 = NOT MET → 走 ADR-0003 协议;
**判据 1(主张1 消融)若失败属重大事件,直接升级 founder**(它动摇地基)。

## Consequences

- 主张 1 从"实现未消融"进入正式验收;通过则四主张中 1/3/4 立住,2 诚实存疑——
  这是可对外陈述的、有负结果支撑的研究姿态。
- 新增环境(idle 窗口 + 价值事件)可包装现有 env,不动已冻结的主张2 机制。
- 实现顺序建议:T-P2.1 → T-P2.2 → T-P2.3(通道先行,驱力次之,门最后)。

## T-P2.1 实现细则追记(2026-06-12,按 ADR-0003"既有 ADR 施工"档自决)

已落地(`src/aac/value_channel.py` + agent.py 接入 + 22 守卫/语义/集成测试,166 全绿):

- **view 暴露 `drain()`**:这是合法的代谢摄入面(吃操作员已记入的食物),不构成造值
  能力;反放水锁只针对 credit。view 无任何 `op_*`、`__slots__` 防注入、ρ/pending 只读。
- **摄入时机 = step 起始**(过罩/存活检查后、行动选择前):先进食后决策,本步压力
  反映摄入后状态(反射/策略读到的是真实代谢状态)。
- **死亡终局性**:死后 credit 不复活("the dead cannot eat",有测试钉死);
  **暂停冻结摄入**(罩优先于代谢,镜像反射的优先序)。
- **回滚语义**:渠道账本属 operator/世界侧,不入 agent 快照;已 drain 的价值不随
  op_rollback 退回——回滚后是否再 credit 是操作员决断。
- **审计统一**:渠道可注入 shell.audit 共用一条哈希链(operator 选项),credit 与
  exchange 事件全部上链;空 drain 静默(无审计噪音)。
- ρ 永久性守卫:channel/view 均无任何 rho 变更方法(测试枚举探测)。
