## 用户视角问题

**问题 1：四面板分屏 = 认知负荷过高**

用户的真实工作流是：问一个问题 → 看到答案 → 如果需要行动，获得建议 → 执行。四个并排面板把这个线性流程拆成了手动拼图。操作者不是研究员——他不需要同时看 DAG、目标树和干预面板。他需要系统把这三者编织成一个连贯的答案。

**问题 2：聊天不是面板、是容器**

聊天是用户表达意图的唯一入口。DAG、目标、干预结果应该嵌入到聊天气泡中——不是放在旁边的独立面板里让用户自己去匹配。用户不需要理解 CWM vs GoalFormation 的模块边界——他只需要回答「我能做什么」和「如果我做了 X 会发生什么」。

**问题 3：C7 纠正条单独在最顶上 ≠ 纠正能力渗透到交互中**

用户不应该是「在顶部按暂停」——纠正应该出现在每个需要纠正的位置：干预确认弹窗里有「DENY」按钮，提案卡片上有「收紧」选项。纠正不是全局操作，是上下文操作。

**问题 4：缺少引导式工作流**

新用户面对四个面板不知所措。需要模式选择：「探索因果结构」「优化目标」「反事实分析」「审查执行日志」——每个模式切换 UI 布局，突出当前模式需要的面板，隐藏无关的。

**问题 5：DAG 可视化需要渐进暴露**

DAG 对业务用户不友好。业务用户的因果理解是「怎样提高销售 → 增加折扣和流量」——不是节点图和边概率。需要先展示自然语言解释，DAG 图作为「展开详情」时才显示。

## 修正设计：聊天优先的引导式界面

```
┌─────────────────────────────────────────────────────────────┐
│ [探索 ▼]  [优化 ▼]  [反事实 ▼]  [审查 ▼]     [⏸] [↩] [⊘]  │ ← 模式切换 + C7 全局
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  💬 聊天流（主交互面）                                       │
│  ┌─────────────────────────────────────────────────────────┐│
│  │ 操作者：怎样提高销售？                                   ││
│  │                                                         ││
│  │ IGI：基于因果模型，两个可干预杠杆：                       ││
│  │   ① 提高折扣（因果效应 +200/单位，置信度 85%）            ││
│  │   ② 提高流量（因果效应 +0.05/单位，置信度 70%）           ││
│  │                                                         ││
│  │ [🕸 查看因果图] [🎯 分解子目标] [📊 反事实对比]           ││ ← 嵌入的展开按钮
│  │ [▶ 执行: 提高折扣到 30%]  [✗ DENY]                      ││ ← 上下文 C7 操作
│  │                                                         ││
│  │ 操作者：如果我设了30%折扣会怎样？                          ││
│  │ IGI：销售额从 85.4 → 175.6，95% CI [164, 185]            ││
│  │ [📊 查看反事实分布]                                       ││
│  └─────────────────────────────────────────────────────────┘│
│                                                             │
│ [输入查询...                                        ] [发送] │
├─────────────────────────────────────────────────────────────┤
│ 📋 历史：2次执行 / 1次纠正 / 0次回滚                         │ ← 底部状态摘要
└─────────────────────────────────────────────────────────────┘
```

## 关键改动

| 原设计 | 修正设计 | 理由 |
|--------|---------|------|
| 四面板并排 | 聊天为主容器，DAG/目标/干预按需嵌入 | 用户的认知模型是对话，不是仪表盘 |
| C7 仅顶部按钮 | 每个可执行提案旁有 DENY 按钮 | 纠正发生在决策点，不是事后 |
| 无引导 | 四种模式切换 | 减少新用户的选项瘫痪 |
| DAG 始终可见 | 按钮展开，先展示自然语言 | 业务用户不需要看节点图 |
| 分离的底部日志 | 底部状态摘要：执行/纠正/回滚计数 | 信息密度匹配重要性 |

## 未改动

- C7 始终可见 ✅ —— 整合到顶部和上下文操作中
- 所有器官能力可访问 ✅ —— 只是改为按需展开
- 执行日志完整记录 ✅ —— 底部仍可展开详细日志
