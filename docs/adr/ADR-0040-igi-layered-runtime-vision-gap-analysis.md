## 0. 愿景 vs 现状

长远愿景描述了一个三层分层运行系统：

```
L3: 角色内目标生成 → 自主拆解子目标 → 执行 → 纠偏 → 迭代
    边界冲突 → 主动请求外部确认
L2: CWM（因果结构）+ 增量持续学习（不遗忘）+ 治理（角色边界/中断/纠正）
L1: 事件溯源 + 双缓冲原子规则切换 + 资源配额 + 安全沙箱
```

### 现状映射

| 层 | 组件 | 愿景要求 | 当前状态 | 差距 |
|---|---|---|---|---|
| **L1** | 事件溯源 | 全事件回放审计 | `seam_contract.py` 审计链，无回放 | 缺可重放事件日志 |
| **L1** | 双缓冲原子规则切换 | 蓝绿部署规则 | 无 | 缺 |
| **L1** | 资源配额 | CPU/内存/干预预算 hard cap | `GovernedLoop.verify_budget` | 缺系统级配额 |
| **L1** | 安全沙箱 | 进程隔离 | 依赖 OS 端 TrustedLoop | 缺 |
| **L2** | CWM | 干预+反事实 | ✅ 就绪 | — |
| **L2** | 增量持续学习 | 不遗忘，适应漂移 | `CWMMaintenance`（漂移检测+衰减） | 缺反遗忘 |
| **L2** | 治理 | 角色边界+C7+纠正 | ✅ GovernedLoop+C7 | — |
| **L3** | 子目标递归分解 | 顶层目标→子目标树 | `GoalFormationOrgan`（单层） | 缺递归分解 |
| **L3** | 执行纠偏 | 执行偏离→自动修正 | 无 | 缺 |
| **L3** | 边界冲突请求确认 | 超出角色边界→升级 | 无 | 缺 |

## 1. 分层实现路线图（按优先级）

### Phase 2a: L3 子目标递归分解（P0 — 立即）

**当前**：`GoalFormationOrgan.form_goals()` 从 DAG 中选出最大杠杆的单层目标。

**目标**：给定顶层目标（如"最大化利润"），递归分解为可执行子目标树：
```
最大化利润
├── 最大化营收
│   ├── 最大化流量（do 广告投放）
│   └── 最大化转化（do 折扣）
└── 最小化成本
    └── 最小化退款（do 质量控制）
```

每条边都可以被干预数据验证。不可达到的叶节点被标记为 `UNVERIFIED`，只提案不执行。

**实现**：扩展 `GoalFormationOrgan`，增加 `decompose(TopGoal, DAG, max_depth=3)` 方法。递归沿因果链分解，直到子目标落在可干预节点上。

### Phase 2b: L2 增量持续学习——反遗忘（P1）

**当前**：`CWMMaintenance.update()` 追加新观测，漂移时触发全量重发现。

**目标**：增量更新时保留历史学习中获得的因果知识。弹性权重加固（EWC）式正则化——对已确认的因果边施加惩罚，降低其在新数据中的可塑性。

**实现**：在 `CWMMaintenance._decay_edges()` 中增加 `consolidation_weight` 参数。确认次数 ≥ 3 的边获得 consolidation 加成——衰减率降低至原来的 1/10。

### Phase 2c: L3 执行纠偏（P2）

**当前**：`ExecutionBridge.run_discovery_then_act()` 执行干预但不检查结果是否符合预期。

**目标**：每轮执行后比较实际结果与 CWM 预测。若偏差 > 阈值，触发本地重发现或升级（请求外部确认）。

**实现**：在 `ExecutionBridge.execute_intervention()` 中增加 `_verify_outcome()` 步骤。预测值来自 `CWM.predict(do_node, do_val)`，实际值来自执行结果，偏差记录在 `_error_buffer` 中。

### Phase 3: L1 运行时基底（远期——需要 OS 侧配合）

L1 能力大部分属于运行时基础设施，应由 `ai-native-business-data-agent-os` 的 TrustedLoop 提供。当前 OS 端已有部分 L1 能力：

| L1 能力 | OS 端现状 |
|---------|---------|
| 事件溯源 | `OperationTrace` + `TraceStore` 可审计 |
| 双缓冲 | 无 |
| 资源配额 | `verify_budget` 在 seam 层面 |
| 安全沙箱 | `ShellView` + `CorrigibilityShell` |

## 2. 统一前端接口设计（独立于数据产品工作台）

### 设计原则

1. **聊天即主界面**——用户的认知模型是对话。「提高销售 → 系统给出可执行杠杆 + 因果解释 + 置信度」。DAG、目标树、反事实不应该是分离的面板——它们嵌入在对话气泡中，按需展开。
2. **C7 在决策点出现**——每个可执行提案旁有 DENY 按钮。全局暂停/回滚/收紧仍在顶部，但纠正的主要交互发生在提案发出时——不是在事后。
3. **引导式工作流**——四种模式切换，减少认知负荷：探索（理解因果）→ 优化（形成目标）→ 反事实（what-if）→ 审查（执行历史）。
4. **渐进暴露**——业务用户不需要看到节点图作为第一呈现。先展示自然语言解释（「折扣→销售额，效应 +200/单位」），DAG 作为「展开详情」时显示。
5. **所有器官面板通过 `/discover` API 与 core 通信**——独立于企业 OS 数据产品管线。

### 修正后的面板架构（经 ADR-0040-frontend-ux-review 修订）

```
┌─────────────────────────────────────────────────────────────┐
│ [🔍 探索] [🎯 优化] [📊 反事实] [📋 审查]    [⏸] [↩] [⊘]  │ ← 模式切换 + C7 全局
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  💬 聊天流（主交互面）                                       │
│  ┌─────────────────────────────────────────────────────────┐│
│  │ 操作者：怎样提高销售？                                   ││
│  │                                                         ││
│  │ IGI：基于因果模型，两个可干预杠杆：                       ││
│  │   ① 提高折扣（因果效应 +200/单位，置信度 85%）           ││
│  │   ② 提高流量（因果效应 +0.05/单位，置信度 70%）           ││
│  │                                                         ││
│  │ [🕸 查看因果图] [🎯 分解子目标] [📊 反事实对比]           ││ ← 内嵌展开按钮
│  │ [▶ 执行: 提高折扣到30%]  [✗ 否决]                       ││ ← 上下文C7
│  └─────────────────────────────────────────────────────────┘│
│                                                             │
│ [输入查询...                                        ] [发送] │
├─────────────────────────────────────────────────────────────┤
│ 📋 2次执行 / 1次纠正 / 0次回滚 · 反偏见：price(已覆盖)      │ ← 底部状态
└─────────────────────────────────────────────────────────────┘
```

### 与数据产品工作台的分离

| | 数据产品工作台 | IGI 统一前端 |
|---|---|---|
| 定位 | 企业 OS 业务查询→指标→仪表盘 | 受治理智能体的人机交互面 |
| 核心 API | `/runs`, `/report`, `/dashboards` | `/discover`（core API） |
| 用户 | 业务分析师、运营 | 系统操作者、主理者 |
| 交互模式 | 查询→等待→查看结果 | 多轮对话，渐进深入 |
| C7 可见 | 无 | 永久可见——全局 + 上下文决策点 |
| 器官可见 | 无 CWM 概念 | DAG + 目标 + 反事实 + 偏见报告——按需嵌入对话 |

## 3. 实现决策

1. **L3 子目标分解优先**——这是从"单步杠杆选择"到"递归规划"的质变。实现成本低（~200 行），回报极高。
2. **L2 反遗忘紧随其后**——在 `CWMMaintenance` 中加一行衰减乘子。量产系统必须。
3. **L3 执行纠偏**——需要预测-实际比较，已有基础设施。
4. **L1 运行时**——不在此仓库实现。依赖 OS 端 TrustedLoop 提供。
5. **统一前端**——独立于数据产品工作台，新建工程目录。AR 已出，下一步是 PR-08 前端实现规格。
