## 3. AI 问数不可信

问题表现：

- 模型回答看似合理，但无法复核。
- 不知道用了什么数据、什么口径、什么 SQL。
- 模型幻觉或过度推断影响业务信任。

解决路径：

```text
SQL Safety
  -> QueryRun
  -> Quality Check
  -> EvidenceChain
  -> Eval Regression
```

1. `06_方案评估与落地边界/AI_Native_Business_Data_OS_MVP技术选型与工程工作流.md`

## 4. SQL 和数据访问不安全

问题表现：

- LLM 可能生成危险 SQL。
- 访问非白名单 schema。
- 扫描过大、无 limit、无时间范围。
- 敏感数据被模型或工具带出域。

解决路径：

```text
SQL Safety Checker
  -> schema allowlist
  -> SELECT-only
  -> parameter binding
  -> query cost / limit
  -> audit trace
```

## 10. 后端 Python 会不会慢

问题表现：

- 担心 Python 支撑不了企业级后端。
- 担心 Agent、SQL、安全、评测都放 Python 会慢。

解决路径：

```text
Python = 控制面 + 编排层
数据库 / OLAP / 队列 / 专用服务 = 重计算和高吞吐
```

推荐资料：

1. `06_方案评估与落地边界/AI_Native_Business_Data_OS_MVP技术选型与工程工作流.md`
2. `repo_scaffold/README.md`

关键原则：

- Python 适合 API、Contract、Agent Runtime wrapper、EvidenceChain、Eval。
- 不让 Python 承担大规模 OLAP、高频流式计算或重 CPU 任务。
- 真正瓶颈通常是模型调用、数据库查询、网络 I/O 和数据质量。

## 13. 第一个付费客户和旅伴客户从哪里来

问题表现：

- 战略和技术架构已经较完整，但首个付费业务闭环尚未被真实客户验证。
- 免费 POC 容易变成长期试用或免费咨询。
- 如果等 MVP 完成后再找客户，会错过第一年的销售窗口。

解决路径：

```text
30个目标客户触达
  -> 12个深度访谈
  -> 5个二次访谈
  -> 2-3个旅伴客户
  -> 1条可付费业务闭环
  -> POC转付费条件
```

推荐资料：

1. `02_竞争格局与商业化/AI_Native_Business_Data_OS_90天客户发现计划.md`
2. `02_竞争格局与商业化/AI_Native_Business_Data_OS_GTM九问与POC转付费销售手册.md`
3. `02_竞争格局与商业化/AI_Native_Business_Data_OS_GTM与商业化执行方案.md`
4. `05_业务问题与评测样本/黄金业务闭环样本.md`
5. `06_方案评估与落地边界/AI_Native_Business_Data_OS_阶段性落地方案.md`

关键判断：

```text
当前最紧迫的不是继续定义完整 Agent OS，
而是用真实客户验证一个真实业务问题能否形成付费闭环。
```

POC 转付费关键窗口：

```text
W6 复盘价值并提出年费方案。
W8 仍不付费，则按协议退出或重新定义 POC。
```

## 14. 首个业务闭环如何验证

- MVP 容易扩散成“完整 Agent OS”或通用问数平台。
- 客户试点如果没有单一闭环，会变成免费定制项目。

  -> ActionProposal
  -> Approval / Task
