## 一、ROI & 广告投放效率（Queries 1-5）

### Q1: 今日全平台 ROI 概览

| 属性 | 内容 |
|---|---|
| 回答的问题 | #1 今天的ROI趋势如何？ #8 聚光和千川ROI对比 |
| 优先使用 | `resolve_metric("ROI")` 确认口径后再执行 |
| 涉及表 | `ads.daily_performance` |
| 数据量级 | <100 rows/day |
| 注意事项 | `ad_spend=0` 时 ROI 为 NULL，前端用 `COALESCE(roi, 0)` |

```sql
SELECT
    date,
    platform,
    SUM(gmv) AS gmv,
    SUM(ad_spend) AS ad_spend,
    ROUND(SUM(gmv)::numeric / NULLIF(SUM(ad_spend), 0), 2) AS roi,
    ROUND(SUM(juguang_gmv)::numeric / NULLIF(SUM(juguang_ad_spend), 0), 2) AS juguang_roi,
    ROUND(SUM(settle_revenue)::numeric / NULLIF(SUM(qianchuan_ad_spend), 0), 2) AS settle_roi
FROM ads.daily_performance
WHERE date = :target_date
GROUP BY date, platform
ORDER BY gmv DESC;
```

## 二、内容与爆款分析（Queries 6-10）

### Q6: 近 N 天爆款内容排行榜

| 属性 | 内容 |
|---|---|
| 回答的问题 | #9 最近7天爆款内容有哪些？ |
| 排序依据 | 综合互动量 = likes + comments + shares + saves |
| 性能 | 如 content_performance 为大表，建议加 date + engagement 复合索引 |

```sql
SELECT
    content_id,
    title,
    platform,
    tag,
    content_type,
    SUM(like_count + comment_count + share_count + save_count) AS total_engagement,
    SUM(impressions) AS impressions,
    ROUND(SUM(like_count + comment_count + share_count + save_count)::numeric
          / NULLIF(SUM(impressions), 0) * 100, 2) AS engagement_rate
FROM dwd.content_performance
WHERE publish_date >= CURRENT_DATE - :days
  AND impressions > :min_impressions
GROUP BY content_id, title, platform, tag, content_type
ORDER BY total_engagement DESC
LIMIT :limit;
-- Default: days=7, min_impressions=1000, limit=20
```

## 三、GMV 与收入分析（Queries 11-14）

### Q11: 全平台 GMV 日报

| 属性 | 内容 |
|---|---|
| 回答的问题 | #5 GMV环比增长率 #1 今日概况 |

```sql
WITH today AS (
    SELECT
        platform,
        SUM(gmv) AS gmv_today,
        SUM(order_count) AS orders_today
    FROM ads.daily_performance
    WHERE date = CURRENT_DATE
    GROUP BY platform
),
yesterday AS (
    SELECT
        platform,
        SUM(gmv) AS gmv_yesterday
    FROM ads.daily_performance
    WHERE date = CURRENT_DATE - 1
    GROUP BY platform
)
SELECT
    COALESCE(t.platform, y.platform) AS platform,
    COALESCE(t.gmv_today, 0) AS gmv_today,
    COALESCE(y.gmv_yesterday, 0) AS gmv_yesterday,
    ROUND(
        (COALESCE(t.gmv_today, 0) - COALESCE(y.gmv_yesterday, 0))::numeric
        / NULLIF(y.gmv_yesterday, 0) * 100, 2
    ) AS gmv_change_pct,
    COALESCE(t.orders_today, 0) AS orders_today
FROM today t
FULL OUTER JOIN yesterday y ON t.platform = y.platform
ORDER BY gmv_today DESC NULLS LAST;
```

### Q13: 新品上架 N 天表现追踪

| 回答的问题 | #19 新品上架7天表现如何？ |

```sql

    category,
    launch_date,
```

### Q14: 商品价格带-销量分析

| 属性 | 内容 |
|---|---|
| 回答的问题 | #22 哪个价格段卖得最好？ |

```sql
SELECT
    CASE
        WHEN avg_price < 50 THEN '<50元'
        WHEN avg_price BETWEEN 50 AND 100 THEN '50-100元'
        WHEN avg_price BETWEEN 100 AND 200 THEN '100-200元'

ORDER BY total_gmv DESC;
```

### Q17: 平台活动期 GMV 增幅对比

| 属性 | 内容 |
|---|---|
| 回答的问题 | #26 活动期间GMV增幅对比 |

```sql
SELECT
    platform,
    ROUND(AVG(CASE WHEN is_promotion_period THEN daily_gmv END), 0) AS promo_avg_gmv,
    ROUND(AVG(CASE WHEN NOT is_promotion_period THEN daily_gmv END), 0) AS normal_avg_gmv,
    ROUND(
        (AVG(CASE WHEN is_promotion_period THEN daily_gmv END)
         - AVG(CASE WHEN NOT is_promotion_period THEN daily_gmv END))
        / NULLIF(AVG(CASE WHEN NOT is_promotion_period THEN daily_gmv END), 0) * 100, 2
    ) AS promo_lift_pct
FROM (
    SELECT
        date,
        platform,
        SUM(gmv) AS daily_gmv,
        date BETWEEN :promo_start AND :promo_end AS is_promotion_period
    FROM ads.daily_performance
    WHERE date >= :promo_start - (:promo_duration_days  -- lookback same period before promo
                               || ' days')::INTERVAL
      AND date <= :promo_end
    GROUP BY date, platform
) sub
GROUP BY platform
ORDER BY promo_lift_pct DESC;
-- Default: promo_start='2026-06-01', promo_end='2026-06-18', promo_duration_days=18
```

### Q20: 库存周转预警

| 属性 | 内容 |
|---|---|
| 回答的问题 | #18 哪些商品库存周转>30天？ |

```sql
SELECT
    product_id,
    product_name,
    category,
    current_inventory,
    ROUND(AVG(daily_sales), 1) AS avg_daily_sales,
    ROUND(current_inventory::numeric / NULLIF(AVG(daily_sales), 0), 0) AS inventory_days,
    CASE
        WHEN current_inventory::numeric / NULLIF(AVG(daily_sales), 0) > 60 THEN '严重积压'
        WHEN current_inventory::numeric / NULLIF(AVG(daily_sales), 0) > 30 THEN '需关注'
        ELSE '正常'
    END AS alert_level
FROM ads.product_performance
WHERE date >= CURRENT_DATE - 30
GROUP BY product_id, product_name, category, current_inventory
HAVING AVG(daily_sales) > 0
  AND current_inventory::numeric / NULLIF(AVG(daily_sales), 0) > :threshold_days
ORDER BY inventory_days DESC
LIMIT :limit;
-- Default: threshold_days=30, limit=20
```

## 安全注意事项

所有 Golden Query 均满足以下约束：
1. **纯 SELECT** — 无 INSERT/UPDATE/DELETE/TRUNCATE
2. **限行** — 通过 WHERE + LIMIT 限制
3. **参数绑定** — 使用 `:param` 占位符，禁止拼接字符串
4. **除零保护** — 所有除法使用 `NULLIF(x, 0)`
5. **Schema 白名单** — 仅查询 `ads`、`dwd`、`metadata` schema
