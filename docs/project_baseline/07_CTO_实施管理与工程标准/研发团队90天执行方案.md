# 研发团队 90 天执行方案

> 日期：2026-06-01  
> 面向对象：产品、研发、数据、AI、前端、测试、安全、解决方案团队  
> 目标：在 90 天内交付“DataProduct candidate + EvidenceChain + 受治理行动提案 + Feedback/Trace + KnowledgeAsset candidate”的可演示、可试点、可回归版本。

## 1. 90 天目标

90 天内只完成一个闭环：

```text
业务问题
  -> BusinessIntent
  -> SemanticObject lite
  -> MetricContract
  -> ProviderContract lite
  -> DataProduct candidate
  -> SQL Template / QueryPlan
  -> SQL Safety
  -> QueryResult
  -> EvidenceChain
  -> ActionProposal
  -> Approval lite
  -> Feedback / Trace
  -> KnowledgeAsset candidate
```

不做完整 OS，不做复杂 Marketplace，不做高风险自动执行业务动作。

## 2. 交付物清单

| 类型 | 交付物 | 验收标准 |
|---|---|---|
| 产品 | 首发场景 PRD 和 30-50 个业务问题 | 覆盖 ROI、内容、日报三类 golden loop |
| 数据 | 20 条 golden query 和指标字典 | 每条 query 有参数、表、性能、口径说明 |
| 契约 | BusinessIntent、SemanticObject lite、MetricContract、ProviderContract lite、DataProduct candidate、EvidenceChain、ActionProposal、ApprovalRecord、KnowledgeAsset candidate schema | 有 JSON/Pydantic schema、示例和 schema tests |
| 后端 | Intent API、DataProduct API、Query API、Evidence API、Proposal API、Approval API、Feedback API、KnowledgeAsset API | 有 unit tests 和 trace id |
| SQL 安全 | SQL Safety Checker | 写操作、非白名单 schema、缺 limit、字符串拼接 100% 拦截 |
| AI | 单一 Agent Runtime 封装 | 结构化输出，不直接绕过契约 |
| 评测 | Eval Harness | golden query、intent、metric、evidence completeness、action risk 全覆盖 |
| 前端 | Intent Workspace、DataProduct View、EvidenceChain Viewer、ActionProposal Panel、KnowledgeAsset Review | 业务 owner 能看懂证据来源、限制、建议和可沉淀资产 |
| 安全 | 风险等级、审批 lite、审计字段 | R4/R5 只提案，不自动执行 |
| 运维 | 本地启动、测试、回归、发布说明 | 新人可按文档跑通 smoke |

## 3. Sprint 计划

建议 6 个双周 Sprint。

| Sprint | 目标 | 关键输出 |
|---|---|---|
| Sprint 0 | 场景和数据冻结 | 首发业务域、问题样本、指标 owner、数据源、权限和敏感字段清单 |
| Sprint 1 | 契约和评测骨架 | schema、golden query registry、eval harness、SQL safety baseline |
| Sprint 2 | 可信数据产品主链路 | BusinessIntent -> SemanticObject lite -> MetricContract -> ProviderContract lite -> DataProduct candidate -> QueryPlan -> QueryResult |
| Sprint 3 | EvidenceChain 产品化 | EvidenceChain builder、viewer、evidence completeness test、trace 串联 |
| Sprint 4 | ActionProposal 和审批 lite | 提案生成、风险等级、审批建议、反馈表、golden loop 1 跑通 |
| Sprint 5 | 闭环回归和试点准备 | 3 条 golden loop、UI smoke、回归报告、试点 runbook |

## 4. 工作流

每个需求按以下顺序推进：

```text
业务问题样本
  -> Contract 设计
  -> Threat / Safety 边界
  -> Eval case
  -> Reference implementation
  -> Local smoke
  -> PR review
  -> Regression eval
  -> Release note
```

禁止先写 Agent prompt 再补契约和测试。

## 6. 模块边界

MVP 建议模块边界：

```text
ai-native-business-data-agent-os/
  packages/
    contracts/
    os_core/
      intent_parser/
      semantic_runtime/
      data_product_compiler/
      query_runtime/
      sql_safety/
      evidence_chain/
      action_proposal/
      approval_lite/
      feedback/
      operation_trace/
      snapshot_store/
      knowledge_memory/
      model_gateway/
    sdk/
  apps/
    api_server/
    workspace/
  domain_packs/
    content_commerce/
  providers/
  action_connectors/
```

核心约束：

- Core 不 import 内容电商具体业务对象。
- Core 不 import 具体平台 SDK。
- Provider 只通过 ProviderContract 暴露能力。
- Business Agent 只消费 DataProduct candidate 和 EvidenceChain，不直接绕过证据链调用底层数据源。
- 高风险动作只能生成 ActionProposal，不自动执行。

## 8. EvidenceChain 必填字段

每个正式答案必须包含：

- 原始业务问题。
- 解析后的 BusinessIntent。
- 命中的 MetricContract。
- 指标口径和 owner。
- 使用的数据源、表、字段。
- SQL Template / QueryPlan。
- 参数值。
- SQL Safety 校验结果。
- 权限和数据范围说明。
- 查询结果摘要。
- 数据质量检查结果。
- 结论、置信度、限制。
- 行动提案引用。
- Trace id。

缺失任一关键字段，输出只能标记为 draft，不允许进入正式业务决策。

## 9. Golden Loop 验收

90 天至少跑通 3 条 golden loop：

| Loop | 验收 |
|---|---|
| 投放效率诊断 | ROI 查询、昨日对比、低效计划排行、行动提案、证据链引用 |
| 爆款内容挖掘 | 爆款排行、共同特征、达人推荐、策略建议、证据链引用 |
| 日报全景扫描 | GMV、订单、ROI、转化率、异常提示、可跳转下钻 |

每条 loop 都必须有：

- 业务问题输入。
- 工具调用记录。
- DataProduct candidate。
- EvidenceChain。
- ActionProposal。
- ApprovalRecord。
- FeedbackEvent。
- KnowledgeAsset candidate。
- Eval case。

## 10. Definition of Done

一个功能完成必须同时满足：

1. 有明确业务问题或验收场景。
2. 有 Contract 或不改变 Contract 的说明。
3. 有 unit test。
4. 涉及 Agent 输出时有 structured output validation。
5. 涉及 SQL 时通过 SQL Safety test。
6. 涉及正式答案时通过 EvidenceChain completeness test。
7. 涉及行动建议时有 risk level 和 approval recommendation。
8. 涉及业务反馈时生成或更新 KnowledgeAsset candidate。
9. 有 trace id 可回放。
10. 有至少一个 eval case 或明确说明不需要。
11. PR 描述回答工程标准中的 8 个问题。

## 11. 周会和评审机制

| 会议 | 频率 | 参与人 | 输出 |
|---|---|---|---|
| 研发站会 | 每日 | 研发小队 | 阻塞、当天交付 |
| 业务评测会 | 每周 | 业务 owner、PO、数据、AI、QA | 新样本、失败案例、口径确认 |
| 风险评审 | 每两周 | CTO、Security、Backend、AI | 权限、SQL、Agent、数据出域 |
| Sprint Demo | 每两周 | CEO/CTO/业务 owner/团队 | 可运行闭环、指标、风险 |
| Release Review | 每次发布前 | CTO、QA、Security、Owner | release gate 结果 |

## 12. 90 天退出标准

90 天后，如果满足以下条件，进入 DataProduct v1 阶段：

- 20 条 golden query 稳定运行。
- golden query 正确率 >= 85%。
- 核心指标口径命中率 >= 90%。
- 正式答案 EvidenceChain 覆盖率 100%。
- SQL Safety 对写操作和非白名单 schema 拦截率 100%。
- 至少 3 条 golden loop 跑通。
- 至少 5 个 DataProduct candidate 被业务 owner 复用或复核。
- 行动提案被业务 owner 真实采纳或转成任务。
- 至少 3 个 KnowledgeAsset candidate 进入人工 review 队列。
- 失败样本能进入 eval 回归集。

如果不满足，不扩大平台范围，只修可信闭环。
