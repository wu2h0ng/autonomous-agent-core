# AR-20260614: P5.1b-ii — non-bypassable grounding invariant (SQL Safety + EvidenceChain)

- Status: Accepted (founder-directed P5.1b-ii execution, 2026-06-14)
- Parent: `docs/decisions/ADR-0001-p5-substrate-harvest.md` (§3 acceptance P5-1; §4 P5.1b row)
- Touches (requires AR per CLAUDE.md): SQL Safety / EvidenceChain / ActionProposal behavior. OS Core only; no contract/schema change.

## 1. Context — convention vs enforced invariant

The Trusted Loop already runs SQL Safety (blocks when not allowed) and builds an EvidenceChain whose builder raises on incompleteness, and `EvidenceChain.is_complete()` already requires `sql_safety.allowed`. So a grounded answer is produced **today** — but the guarantee is *distributed and implicit*: it lives in the linear order of `_execute_loop` plus the builder's own check. CLAUDE.md states it as a convention ("All formal data answers must pass through SQL Safety and EvidenceChain"; "Business Agent logic must not bypass the data/evidence path"). ADR-0001 §3 P5-1 requires elevating it to an **enforced, bypass-is-failure invariant** at the Trusted Loop — the "non-bypassable mediation" (stake = claim 1 harvest, P5 memo M3).

## 2. Decision

**A single, explicit grounding checkpoint gates every formal answer/proposal/execution.** No `TrustedLoopResult`, `ActionProposal`, or connector execution may be produced without (a) the query having passed SQL Safety and (b) a complete `EvidenceChain`.

- New typed `GroundingInvariantViolation(Exception)` in OS Core — a **hard breach**, distinct from `TrustedLoopBlocked` (an expected, user-facing business block). Reaching it means the data/evidence path was bypassed by a wiring/refactor bug; the loop fails loudly instead of emitting an ungrounded answer.
- `TrustedLoopRuntime._assert_grounded(safety, evidence)` raises it if `not safety.allowed` or `not evidence.is_complete()`. Called once in `_execute_loop`, **immediately after the EvidenceChain is built and before the ActionProposal/operation/result are produced** — so the proposal, governed execution, R4/R5 halt, and answer are all downstream of the single checkpoint.

This is defense-in-depth and centralisation: even if the EvidenceChainBuilder were refactored to skip its own check, or a future surface tried to answer from the model bypassing the data path, the loop's mediation invariant trips.

## 3. Engineering-flow specification

- **Real entry point**: `TrustedLoopRuntime.run` / `evaluate` (every formal answer flows through `_execute_loop`, which now calls `_assert_grounded`). Exercised by every existing run test plus the new grounding tests.
- **Contract/schema**: unchanged. Reuses `SQLSafetyResult.allowed` and `EvidenceChain.is_complete()` (which already encodes `sql_safety.allowed`).
- **Happy path**: a grounded run passes the checkpoint silently; `result.action_proposal.evidence_chain_id == result.evidence_chain.evidence_chain_id` and `result.evidence_chain.is_complete()`.
- **Negative/refusal paths**: unsafe SQL still blocks at `sql_safety` (TrustedLoopBlocked, unchanged); an *ungrounded* evidence reaching the checkpoint raises `GroundingInvariantViolation` (a breach, not a block).
- **Regression that fails if bypassed**: `test_loop_refuses_ungrounded_evidence` injects an evidence builder that returns an ungrounded EvidenceChain (simulating a refactor that bypasses the data/evidence path); the loop raises `GroundingInvariantViolation` instead of returning a formal answer. If the invariant were removed, this test fails.
- **Trace/evidence/feedback/knowledge**: unchanged on the happy path; the checkpoint adds no telemetry beyond the existing `evidence_chain` records.
- **OS Core boundary**: entirely within `agent_os_core`; no new imports of domain/persistence/connectors.

## 4. Acceptance (ADR-0001 §3)

```text
P5-1  No ActionProposal, governed execution, or TrustedLoopResult can be produced unless the
      query passed SQL Safety AND the EvidenceChain is complete. A bypass of the data/evidence
      path raises GroundingInvariantViolation — proven by a regression that fails if the
      invariant is removed.
```
